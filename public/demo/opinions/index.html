Atlas — unstructured opinion agent

Architecture

Three retrieval/compute routes plus an orchestrating LLM: document-level vectors for similarity and outliers, a chunk-level hybrid index for passage search, and a deterministic filter + exhaustive scan for completeness questions. Each tool survives only where the others fail.

Document-level embeddings

One point per opinion. Answers the natively document-grained questions — "which opinions are like this one," precedent sets, outliers. Hybrid of lexical TF-IDF and common-direction-corrected neural vectors.

[ placeholder — interactive 3D atlas: 583 docs, cluster rail, pinned deals ]

find_similar — precedents / "opinions like X" · mode=outliers for "what's unusual"

Chunk-level embeddings

~600-token chunks, section-header-aware, tables typed separately. The fast path for "where does anyone say X" — top-k with page citations, hybrid with BM25 so exact terms survive.

[ placeholder — retrieval walkthrough: query → top passages with page cites ]

search_passages — hybrid chunk retrieval, top-k, never exhaustive
read_document — exact wording once search locates the spot

Exhaustive scan

For questions where completeness matters ("average discount rate across all matching deals"): deterministic filter, then a cheap LLM reads every matching document and returns strict JSON, aggregated in code — not by the model.

[ placeholder — scan pipeline: filter → per-doc extraction → calc → aggregate ]

scan_documents — mode=regex (free, exact) · mode=extract (per-doc LLM reader)
calc — guarded arithmetic, no mental math on lists of numbers

The agent

A strong orchestrator over six tools: pinned operationalizations live in tools, counts never come from top-k, every claim cites [deal, doc-kind, page], abstention names the missing thing.
